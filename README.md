# Менеджер нотаток — серверна частина

REST API для створення та пошуку нотаток, організованих за категоріями й тегами. Проєкт підготовлений як серверна частина теми 6 для навчальної практики.

## Технології

- Node.js 20 або новіший, Express 5
- SQLite для локального зберігання даних, Sequelize ORM
- Umzug для версійованих міграцій
- Awilix для Dependency Injection
- CORS, Morgan, Pino та централізований обробник помилок
- OpenAPI 3 / Swagger UI

## Запуск

У корені проєкту виконайте:

```powershell
npm install
Copy-Item .env.example .env
npm run migrate
npm start
```

Для pnpm замість першої команди можна виконати `pnpm install`; конфігурація проєкту дозволяє потрібний інсталяційний скрипт `sqlite3`, який встановлює його нативний модуль.

За замовчуванням API працює на `http://localhost:3000`. Swagger UI доступний за адресою `http://localhost:3000/api-docs`, перевірка стану — `http://localhost:3000/health`.

Параметри запуску зберігаються у `.env`. SQLite-файл за замовчуванням створюється в `data/notes.sqlite`; файл бази та секрети виключені з Git через `.gitignore`. Під час запуску сервера застосовуються ще не виконані міграції.

## Ресурси та зв'язки

- **Notes** — назва, текст, необов'язкова категорія й набір тегів.
- **Categories** — назва та опис; при видаленні категорії нотатки залишаються без категорії.
- **Tags** — назва; при видаленні тегу зв'язки з нотатками видаляються.

Одна категорія може містити багато нотаток. Нотатка може мати багато тегів, а тег може бути використаний у багатьох нотатках. Схема створюється міграцією `migrations/202610100001-create-notes-schema.cjs`.

## API

Усі ресурси мають `GET` для списку та одного запису, `POST`, `PUT`, `PATCH` і `DELETE`:

| Ресурс | Шлях | Особливості |
|---|---|---|
| Нотатки | `/api/notes` | `q`, `categoryId`, `tagId` для пошуку та фільтрації |
| Категорії | `/api/categories` | Відповідь містить пов'язані нотатки або їх кількість |
| Теги | `/api/tags` | Окрема сутність для призначення тегів нотаткам |

`PUT` замінює ресурс, а `PATCH` змінює лише передані поля. Після видалення категорії пов'язані нотатки лишаються без категорії.

Приклад створення нотатки:

```json
{
  "title": "План на тиждень",
  "content": "Підготуватися до практики",
  "categoryId": 1,
  "tagIds": [1, 2]
}
```

Фільтрування: `GET /api/notes?q=практика&categoryId=1&tagId=2`. Для повного опису параметрів, схем і відповідей відкрийте Swagger UI або файл `docs/openapi.yaml`.

## Структура коду

Запит проходить через middleware до маршруту, контролера, сервісу й репозиторію. Контролери перевіряють вхідні дані та формують HTTP-відповідь; сервіси містять правила предметної області; репозиторії виконують запити через Sequelize. Залежності реєструються в `src/container.js` і передаються через Awilix. Morgan записує HTTP-запити, Pino — помилки та ключові операції.

## Перевірка через Postman

Імпортуйте `postman/notes-manager.postman_collection.json` у Postman та запустіть запити послідовно. Колекція створює тестові категорію, тег і нотатку, зберігає їхні ID як змінні та містить запити для CRUD, пошуку, валідації й відсутніх записів. Результати запуску колекції або скриншоти Swagger UI потрібно додати до звіту після фактичного тестування.

Автоматизовану перевірку HTTP-сценаріїв можна повторити, поки сервер працює, в іншому терміналі командою `npm run test:smoke` (або `pnpm test:smoke`). Вона перевіряє CRUD усіх трьох ресурсів, пошук, валідацію межі довжини назви та відповіді для помилкових і відсутніх записів; створені під час перевірки записи видаляються.
